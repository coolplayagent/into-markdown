# Markdown 输出与消费端

普通正文和 Markdown 表格优先使用 `**粗体**`、`*斜体*`、`~~删除线~~`。
相邻且样式相同的文本在输出时合并，IR 内的文本、标记和来源保持完整。
边界空白放在 Markdown 分隔符之外；标点、嵌套或相邻分隔符不能可靠表达时，
保留行内 HTML。下划线、上下标和复杂 HTML 表格继续使用对应 HTML 标记。
正文显式换行使用两个空格加 LF，表格单元格和 HTML 上下文使用 `<br>`。
正文段首的 Tab 或四个以上空格用字符实体保护，避免被消费端误判为代码块。

列表正文省略内部 `source-marker` 注释，IR 的 `marker_label` 保留自定义编号和
原始标记。Markdown 使用标准数字、项目符号和任务状态，保留起始编号、空项与嵌套。
相邻的独立列表之间使用空 HTML 注释隔开，防止 CommonMark 消费端合并列表后丢失重启编号。
该分隔符不包含来源数据。
续行缩进随数字标记宽度增长；超过 Markdown 九位数字限制的列表使用 HTML `ol start`。

CLI 将文件系统路径按段转换为 URI：保留可读 Unicode，编码空格、`# ? % &` 等字符。
文件名中的字面 `%20` 会生成 `%2520`；API 的 `asset_uri_prefix` 属于 URI，已有转义
保持稳定。资源仍由统一 AssetPlan 生成安全文件名；路径安全和同盘符/同 UNC share
限制不变。完整输出策略见 [CLI](cli.md)。

PPTX、PPT 和 ODP 的生成备注标题统一为三级 `Speaker notes`。空占位符与纯空白
不生成标题。图片在 extract/embed 下保留，在 omit 下保留 alt 或 OCR 等有效文字；
最终没有可见内容时省略整个备注区。转换器通过节点身份标记生成备注，普通用户正文里
同名的标题不受影响。节点来源定位继续保留，身份可随 ZIP 前缀及 OCR 节点派生传递。

Web 阅读预览是受限消费端：支持原生粗体、斜体、删除线、嵌套、转义和现有行内样式，
使用有界扫描与惰性文本回退。HTML、外链和图片文本不会生成可加载任意资源的 DOM。
检查图片实际加载应使用支持图片的 Markdown 消费端，并同时核对解析后的 URI、文件存在性
和资产字节摘要。
