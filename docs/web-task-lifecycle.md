# Web 任务生命周期与本地验收

页面沿用原有布局。任务运行归应用级 `TaskRuntime` 管理，路由负责显示与交互；服务端持久记录决定接收和任务状态。

## 问题来源与处理

原工作台在页面内逐文件等待提交响应，上传准备、队列等待会阻塞后续文件。页面卸载会释放观察连接，整批完成后才触发结果导航。结果加载还串联批次查询与正文读取，读取完整产物时需要复制及完整性检查。这些等待叠加，容易表现为某一文件停住、结果迟迟不可见。

当前提交冻结批次配置和授权，以稳定提交 ID 创建接收凭据，再流式上传正文。文稿与转录共用两个上传槽位；每个文件独立进入处理队列。服务端完整落盘后返回接收状态，指纹准备和任务创建在后台完成。传输响应丢失先查询凭据，避免重复提交。累计摘要与原恢复指纹保持一致；未知长度或重启恢复使用有界流式计算。重试流式复制输入，并在持久请求中保留原任务关联。

前端状态管理位于路由之上。上传显示等待、上传百分比和接收准备；任务显示服务端阶段与资源等待信息。批次中任意文件完成后即可主动打开，当前文件列表每页最多一百项。浏览器仅保存文件描述、提交和批次标识，刷新后恢复已接收任务，未传完正文需重新选择文件。录音草稿继续使用原有受控存储。

## 查询与结果读取

- `POST/GET/PUT/DELETE /api/uploads/{submissionId}`：创建、查询、传输及取消接收凭据。
- `POST /api/tasks/summaries`：每次最多一百个任务，返回服务代次、事件序号和执行阶段，省去产物枚举与完整性读取。
- `GET /api/tasks/{id}/detail`：结果页需要的任务和产物描述。
- `GET /api/tasks/{id}/previews/{key}`：最多 256 KiB 的 UTF-8 正文预览或诊断摘要；并发读取上限为两个。
- 历史查询支持工作流、批次、状态、固定、名称搜索和游标分页。启动时从可信请求记录回填可重建索引。

前端使用一个不重叠的轮询调度器，前台一秒、后台五秒，错误指数退避至三十秒，恢复焦点立即同步。终态停止请求，服务序号和任务时间戳阻止旧状态覆盖新状态。兼容事件流在终态关闭，并在取消时释放读取资源。

结果框架先显示，正文、完整批次导航和说话人信息分别读取。预览在发布时生成，按任务、产物代次与摘要缓存，切换结果取消过期读取；历史产物按需校验并生成预览。完整下载继续使用原有产物完整性保护。解析限制正文行数、表格单元格和行内工作量，禁止正文生成可执行内容或自动加载外部资源。

## 存储与资源边界

数据库迁移保留既有任务及恢复记录，增加查询投影、接收凭据和预览。大于 SQLite 单行限制的受限 JSON 分块存储，更新在一个事务内提交；产物摘要约束预览复用。新接收和预览写入继续执行原有元数据空间预留。

上传和下载快照采用短锁预留、锁外文件 I/O、守卫释放资源。历史清理分页扫描期间释放数据库锁，删除时先完成文件隔离，再提交持久删除；保留原有恢复和隔离校验。维护循环启动后及每五分钟执行一次，容量压力通过合并信号提前触发，上传路径持续校验硬配额。转换 worker、OCR、内存、临时空间与授权契约沿用原实现。

## 验证方式

任务存储与前端单测纳入现有 Linux x86_64 共享/Web job，后端 CLI 生命周期与 HTTP 回归在本地执行，保持五分钟 CI 边界；无新增 CI workflow、job 或触发方式。`web/console/tests/task-flow-local.mjs` 是本地串行浏览器验收脚本，使用已安装的 Edge 和指定候选二进制：

```sh
INTO_MD_CLI="$PWD/target/web-install/bin/into-md" \
INTO_MD_BATCH_COUNT=102 \
NODE_OPTIONS=--max-old-space-size=512 \
node web/console/tests/task-flow-local.mjs
```

可用 `INTO_MD_LARGE_PPTX` 指定大文件。脚本暂停 PPTX 上传，验证 XLSX 独立完成、结果可读、切页持续和刷新恢复，并采样二十次预览、三十次状态查询；输出 `target/web-browser-metrics.json`。测试使用隔离的数据目录，结束后关闭浏览器和服务并清理目录。Rust 本地验证设置 `CARGO_BUILD_JOBS=1`，Node 限制 512 MiB 堆，验证串行执行。服务端终态事件历史最多保留 256 项，事件缓存省去完整附件清单；最近任务的持久状态快照可在数据库繁忙期间继续响应。设置 `INTO_MD_WEB_TIMINGS=1` 可记录上传、接收准备、排队、转换、发布和预览读取时长，使用提交 ID、任务 ID 和结果代次关联，不记录正文或凭据。

2026-09-18 本机最终采样：仓库 PPTX 加入约 8 MiB 无关填充，搭配仓库 XLSX，另执行 102 文件批次，验证当前列表翻页与结果批次导航完整。重复打开已发布结果的预览 P95 为 73.6 ms，百任务状态查询 P95 为 5.0 ms，页面脚本错误为零。该文件用于运输与调度隔离验证；复杂文档解析、OCR 内容质量和实际转换耗时须使用对应真实文件单独验收。用户报告问题的原始大 PPTX/XLSX 尚未提供。

候选代码与内嵌前端需一起构建并核对 manifest。当前本机既有安装报告版本 `0.0.0`，本次候选来自 `0.0.7` 工作区；浏览器验收明确启动隔离安装目录 `target/web-install/bin/into-md`，与候选构建核对摘要；用户现有安装保持原样。本机 Bazel Rust helper 依赖 `zerofrom_derive` 构建失败时，已成功生成的 Bazel `generated_assets` 由同一仓库的 Cargo 构建版安全更新器复制，随后核对嵌入索引与每个产物摘要。正式安装产物不能用工作区浏览器结果代替验证。

## 验收边界

本机回归通过任务存储 37 项、Web 后端 80 项、HTTP 接口 18 项、Web 界面 55 个独立用例、管理界面 28 项和 CI 策略 14 项；类型检查、内嵌产物一致性与仓库结构检查通过。Web 用例覆盖前端队列与恢复、预览安全、历史与无障碍，CI 工作流策略保持四个 fast job。新增场景包含未开始上传的取消与重试、服务重启后的接收恢复、终态事件缓存淘汰，以及数据库忙时的轻量查询。

真实扫描 PDF/图片 OCR、音视频转录运行时、慢磁盘压力、长时间内存稳定性和用户原始大文件仍需对应环境与样本验证；操作反馈的一百毫秒目标尚未单独采样。现有每任务资源预算继续生效，跨任务统一内存/OCR 准入仍沿用既有能力；本次未建立进程级总内存治理器。已关联任务的接收凭据、索引与预览随历史删除清理；未关联任务的等待、失败、取消和中断凭据保留三十天，由维护循环每次最多清理一千项，正在上传和接收准备的凭据保留。
