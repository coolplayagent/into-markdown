# 转换质量验收

发布以 best-effort 交付失败为 0、有文字图片 OCR 成功率至少 95%、质量不弱于正式版 0.0.6 为验收标准。优先让可识别图片进入 OCR，并以接近全部识别成功为目标。发布同时执行交付检查和内容检查。CLI 成功退出、`Complete` 或 `Degraded`、资源链接有效和页码覆盖证明交付状态；正文、表格关系、图片文字和阅读顺序由独立内容证据验证。

混合加密 ZIP 在 best-effort 下保留可读成员，并附带完整原包及加密成员定位；全部成员加密时保留不可读取状态。深层 Word 表格按源顺序简化内部结构，保留正文；默认 XML 嵌套范围覆盖类型可表示的深度，用户明确设置的深度限制继续生效。

输入无法读取、用户取消和输出无法写入保留真实状态。未提供密码的加密原件单独列为不可读取输入，保留原始失败记录与错误码，并另报可读取输入的转换失败数。`classify_inputs.py` 只接受绑定原件 SHA-256 的独立加密检查证据；文件名或“负面样本”标签无法豁免转换失败。

## 固定输入与内容证据

PDF、Office、电子书、网页、表格、图片和压缩包使用固定原件及 SHA-256。每个样本记录预期正文片段、结构关系、图片文字、OCR 开关和允许的恢复方式。预期内容来自原件检查；候选程序的输出用于与预期比较。失败样本持续保留，新增样本补充原件与预期。

`tools/pdf-resilience/quality_gate.py` 提供格式通用的内容门槛。它读取冻结的逐篇预期、转换报告、实际 Markdown 和人工复核记录，校验输入与输出哈希、必要文字、OCR 计数守恒、逐篇识别下限、跳过与失败上限及恢复诊断上限。运行缺项、缺少 OCR 统计、内容消失或违反明确的 OCR 与恢复预期时返回失败。`--review-policy source-content` 保留这些内容检查，人工复核作为补充证据；`all-recovery` 另要求所有指定页完成复核。

预期的 `cases` 以 `id` 和 `ocr` 唯一定位，包含 `sourceSha256`、`requiredText`、`exactTextCounts`、`forbiddenText`、`ocrMinimums`、`ocrMaximums`、`diagnosticMaximums` 和 `reviewPages`。所有已有样本必须出现。每个需要 OCR 的固定样本应设置已完成识别和含文字结果的下限，并校验仅存在于图像中的原文片段。

## OCR 统计

报告的 `resourceUsage.ocrRuntime` 区分以下观察：

- `imageSources`：每个 OCR 处理单元中的图像资产数量；包含正式交付图像及内部页面渲染。PDF 按页处理，相同资产跨页出现会分别计数。
- `imagesAttempted`：交给识别处理的图像数量，包含共享识别结果的相同内容资产。
- `imagesCompleted`：取得有效识别结果的图像数量，包含有效空结果。
- `imagesWithText`：有效结果中带有通过文本筛选的文字的图像数量，统计发生在容器合并和去重之前。
- `imagesFailed`：识别处理失败或识别能力不可用的图像数量。
- `imagesSkipped`：未提交识别的图像数量，包含 OCR 关闭、选源排除和外层预检拒绝。
- `requests`：实际分配 OCR 工作进程预算并提交的请求数。

满足 `imageSources = imagesAttempted + imagesSkipped`、`imagesAttempted = imagesCompleted + imagesFailed`、`imagesWithText <= imagesCompleted`。最终合入正文的文字另由 `resourceUsage.ocr` 记录。原文件图片总数、交付图片数、OCR 候选数和工作进程请求数使用各自的统计口径。

有文字图片的识别成功率单独统计：在识别前根据原图确定是否含文字；空白及无文字图片从该分母排除，低清晰度文字保留在分母中。完成一次空结果只表示处理完成，有文字图片还必须交付识别文字才能计为成功。固定图片在正式版 0.0.6 与候选版本运行，报告全部样本、排除理由、尝试、完成、失败、跳过以及文字变化。`tools/pdf-resilience/compare_ocr.py` 校验清单和结果哈希，并执行至少 95% 的成功率门槛；旧版已识别的正文发生变化时门槛失败，要求独立原件复核；布局质量另行核对。

## 恢复与复核

恢复继续提供可读内容并记录原因。针对阅读顺序、表格、公式、脚注和识别异常比较原件与输出，已有逐页复核保留为补充证据。发布使用 `source-content` 策略，不要求完成全部恢复页的人工复核。复核记录绑定原件、Markdown、完整资产清单和候选程序哈希，保存页码、结论及具体观察。旧输出的复核记录无法批准变化后的内容。缩略图概览、全文比较及图像像素核对分别记录。

自动文本召回用于发现可疑页；表格中标签与数值的关联、数学符号、英文空格和图内文字仍需有针对性的内容检查。相同文字集合无法证明阅读顺序正确。

固定的 XML 事件数或图片元数据尺寸不得作为额外中止条件。EPUB、Draw.io、ODF、HTML、Feed 和 RTF 的扫描持续响应取消和超时；TIFF 解码缓冲与元数据使用请求的内存及解压预算；移除要求文件空隙和末尾均为规范填充的校验，保留实际目录、数据区间、重叠、循环和越界检查。RTF 字体与诊断列表随请求内存预算增长，字段捕获使用配置的字段大小限制。整数可表示范围、格式有效性和用户明确设置的资源限制继续生效。

轻量回归进入现有四个 fast CI job；真实语料与完整运行时专项在本地执行。发布证据同时给出转换通过数量、内容门槛结论和未完成复核项目。仅完成转换的历史运行保留为诊断证据。

`ocr_contract_corpus.py` 将同一已核对的 OCR 图像放入多种容器，指定句子仅存在于图片像素中。自动 OCR 必须恢复完整句子且恰好出现一次，关闭 OCR 则校验资产保留和未执行识别。ZIP 由成员转换承担 OCR，归档合并阶段复用成员结果。

EPUB 目录与正文中的内部链接绑定到交付的章节锚点。源片段无法精确映射到 IR 时记录 `epub.link.chapterLocation` 警告，并定位到包含该片段的章节。章节原文与源片段仍用于内容复核。

格式识别阶段的失败同样进入 best-effort 恢复：已声明为支持格式且可读取的文件，保留原件和具体原因；Office 加密容器通过目录中的加密流识别并返回加密状态。邮件中未被正文引用的、经过图像校验的 CID 图片在附件区展示并进入 OCR，正文已引用的图片保持一次展示。图片编解码类型由实际字节识别，纠正附件 MIME 与扩展名误标，复用图片转换器的格式校验。

分阶段验证使用 `reconcile_reports.py` 关联完整清单、既有运行与修复后的专项复测。每条结果保留对应可执行文件和原报告的 SHA-256；清单缺项、源文件变化或新出现的复测失败均会阻止验收。组合报告明确标为多产物验证，原始失败记录保留。发布说明分别列出完整语料运行、变更涉及的专项复测和正式安装产物验证。

批量证据按 OCR 模式分别汇总计数。`auto` 的跳过数量用于检查默认识别覆盖，`off` 的跳过数量记录用户明确关闭 OCR 的行为。嵌入图像以原始附件交付时，缺少替代文字的下载链接使用可见标签。

Rust 集成中，`SourceLocator` 新增可选的 `text_baseline`，用于保留原生 PDF 的真实文字基线并正确定位上下标。直接构造该结构体时补充 `text_baseline: None`，或使用 `..Default::default()`。JSON 中缺失该字段仍按 `None` 读取，值为空时保持原有输出形状。

Web 遇到只有远程 URL 的源图片时保留链接与正文，提供 Markdown、文档数据和可用本地资产；便携包因缺少图片原始字节而不可用，结果显示降级及 `webBundleExternalAssets` 原因。该交付路径不主动下载远程资源，本地输出写入失败仍保留真实失败状态。

PNG 编码完成后释放未使用的预分配空间，持有预算按压缩后容量核算。连续页面和图片帧的回归检查累计预算、像素保留与显式编码资产大小限制，防止未压缩工作区挤占后续 OCR 资源。

`audit_ocr_completion.py` 单独检查每份文档的 OCR 处理完成率至少 95%，并检查恢复页面图像确实进入 OCR；转换成功无法豁免处理错误。完全透明图片的排除同时绑定输入和图像 SHA-256。此处理门槛与有文字图片识别率门槛分别执行，空结果只计为处理完成。

PDF 提取图片以无损 PNG 发布，保留分辨率、颜色与透明度；整页 OCR 工作图在页面事务结束后释放。连续扫描页回归同时核对压缩后的保留内存与解码像素，避免未压缩 BMP 跨页累积挤占 OCR 工作空间。默认验收中的资源跳过数量纳入 OCR 覆盖门槛，不能仅用已尝试图片的完成比例掩盖大量未尝试图片。

图片略超出页面边界或缺少可直接映射的坐标时，PDF 默认 auto 使用显示页面的渲染图进行 OCR，保留裁剪后的可见内容；记录 `pdf.pageOcrPlacement` 及页码。原始图片由该页面的 OCR 覆盖，免于重复识别。验收将定位跳过与资源跳过一并检查，并对扫描页、恢复页和定位恢复页核对至少 95% 的 OCR 完成覆盖。
