# ADR 0001：所有转换都经过统一 IR

状态：已接受

包括 PDF、OCR、音频、视频和 AI 辅助转换在内的所有转换器，都生成相同的
`Document` IR。只有中央渲染器负责生成 Markdown。

这样可以统一修复渲染问题、保留溯源信息，并防止提供者响应绕过验证。转换器不得
将 Markdown 作为主要内部表示返回。

## 稳定线协议与兼容性

`Document` 自身携带 `schemaVersion`，避免嵌套在由不同调用方自行定义的信封中。
`into-markdown-core` 是版本常量、JSON 编解码和递归验证规则的唯一所有者。所有公开
IR 结构使用 lowerCamelCase 字段；`Block` 与 `Inline` 使用显式的 `type` 和 `data`
判别字段，因而 Rust 类型名和枚举内部布局不会意外改变线协议。

同一 schema 版本内只允许兼容性新增：读取方忽略未知对象字段，新增字段必须可选
或具有默认值，已有字段及枚举判别值不得改变含义。删除、重命名、改变必填性、改变
数据类型或增加旧读取方无法保留的枚举判别值时必须递增 `schemaVersion`。实现若声明
支持多个历史版本，必须先迁移为当前内存模型再验证；当前只有版本 1，未知版本返回
稳定的 `unsupportedSchemaVersion`，不得猜测或部分解析。

不可信 JSON 必须通过 `Document::from_json` 进入系统，内存中由转换器或提供者构造的
文档必须在消费前调用 `Document::validate`。验证递归覆盖所有节点、嵌套容器和溯源，
错误提供稳定代码及 JSON 风格路径；描述文字不属于稳定接口。

公共解码和验证入口使用明确的 JSON 字节数、嵌套深度、结构节点数、inline 节点数和
表格逻辑列数预算，超限返回 `resourceLimit`。表格验证使用有界占用网格，保证每行
逻辑宽度一致并拒绝跨度重叠或越界。`SourceLocator.part` 只接受不含空段、`.`、`..`、
反斜杠或控制字符的容器相对路径，并拒绝绝对路径、盘符和 UNC 形式。
JSON 解码在构造 typed `Document` 前先以显式任务栈预检这些结构预算，构造后仍执行
完整语义验证，形成两层防线；无法识别的畸形 wire shape 继续由 Serde 拒绝。
